# Development 模块

继承根目录约定，职责与接口见 [docs/MODULES.md](../../docs/MODULES.md)。

- 工作区、任务记录、执行事件模型与开发提示集中于本目录；不实现第二套 Codex 协议或权限系统。
- 本目录不依赖 UI、后端或 egui；原生 viewport 与交互状态放在 `src/ui/development.rs`。
- 开发指令仅在 developmentMode 开启时注入；模式切换须新建会话，不能恢复带有旧模式指令的线程。任务和工作区隔离，外部路径不得跨项目复用线程。
- 工作区记录是私人用户数据，使用独立状态文件、原子保存、Unix 0600；损坏文件不得覆盖，运行中任务恢复为中断，不当成成功。
- 测试只用临时项目和模拟协议，不读取真实用户任务、登录或模型。

- 私人状态当前版本 3，兼容迁移版本 1/2 并保留任务；诊断按真实路径验证项目归属，空快照表示清空。测试领域仅描述 argv/结果，执行必须复用 backend 的 app-server command/exec，不能隐式拼 shell 或扩大本机沙箱。
- 项目记忆只载入 confirmed && enabled 且文件依据仍匹配的条目；依据用项目内路径与 SHA256，源文件变化须失效。记忆 revision 与载入文本 stamp 同时绑定任务，变更后不得恢复带旧背景的线程。保存失败不得更新记忆或丢弃编辑草稿。

- Turn.supplements 只保存确认成功且已遮蔽的运行中补充；保持 user 原文和同一轮次，缺失字段默认空数组以兼容旧历史。补充发送时捕获 OutputBoundary，成功确认才连同文本记入 SupplementAt；边界中的回复前缀及 ID 同步遮蔽并随检查点保存，不能只靠未压缩日志或消息 ID 推断前后输出。

- Manifest 是本程序提供内容的发送证据，不是 Codex 完整历史；预览与实际写入分开，静态设定标为沿用会话，历史测试不自动注入。实际协议文本必须来自同一份已冻结的选择，记忆 stamp 绑定该选择。
- 新 Turn 的变更通过 activity/text → 遮蔽已组装文本 → flush_events，以及 set_manifest/supplement/finish 记录；禁止只改投影绕过日志。回放不执行工具；旧任务不补日志，容量上限用检查点或明确不完整处理，未知版本/序号缺口/快照不一致拒绝覆盖。

- 文件汇总使用本轮累计 diff 优先、工具 patch 补缺，不能用整个工作区 Git diff 冒充本轮改动。结束快照须先遮蔽再经 Review 日志保存；全文只读取项目内普通文件并限量，差异核对失败保留证据并明确回退，旧任务不读取当前文件伪造历史。
