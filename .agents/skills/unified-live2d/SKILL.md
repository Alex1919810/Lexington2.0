# 统一 Live2D 风格角色制作

目标是一个可扩展的统一角色：不同动作共用画布、原画、分层、基准姿态和待机时钟。GIF 是审核预览，正式交互由同一角色的局部参数驱动。自定义素材包不等于 Cubism moc3 模型，也不等于已经接入点击控制。

## 工作顺序

1. 确认源立绘和已认可版本；明确本次要做哪些动作、哪些部位应保持不变，以及目标是预览、素材包还是实际应用接入。用户只要求手部动作时，不自动添加眨眼；用户要求保留呼吸时，修手臂不能顺便关闭呼吸。
2. 读取 [authoring.md](references/authoring.md)。先建立同一 neutral 基准与共享图层，再补局部动作；保留身份、画风、手臂粗细、花束等原有细节。需要位图生成/修复时，用当前可用图像生成工具并先检查参考图；核对实际输出画布和 alpha，不把请求尺寸或透明标志当作成功证明。
3. 读取 [actor-contract.md](references/actor-contract.md)，把共享待机、动作参数、通道所有权、热区和图层变换写成相对路径素材描述。使用 `scripts/actor_core.py` 的时钟、轨道、固定 IK 分支和坐标逆变换作参考；所有坐标与幅度来自当前模型，不复制案例坐标。
4. 先看静态 neutral / 中间 / 极值姿态，确认原画轮廓和关节连接，再渲染运动。头发飘动或加大摆幅时读取 [hair.md](references/hair.md)，先确认发束保形、切分边界与遮挡。眨眼仅在需要眼部通道时读取 [eyes.md](references/eyes.md)，使用保留的 `scripts/reference_blink.py`，不是自动给所有动作加眨眼。
5. 按 [quality.md](references/quality.md) 检查实际编码文件、随机相位触发与动作叠加。共享调色板导出统一 GIF；运行 `scripts/audit_actor.py` 检查素材描述、动作归位、文件引用和预览首尾。数值通过仍需查看整段动画及局部放大。
6. 交付共同 neutral、分层/图集、动作与热区数据、并排预览和连续触发预览，说明当前是否已接入应用。实际接入时沿用目标工程技术栈，先读取项目规则；离线 Python 工具不能成为原生应用新增的运行依赖。

在 Lexington 项目中接入时，另读 [lexington.md](references/lexington.md)，确认原生格式、资源目录、代码边界与最终透明合成验证入口。

## 统一原则

- **一套角色，不是分别重绘整个人物。** 新动作沿用已认可的原画和图层，仅修改拥有的局部通道。每次独立生成完整 GIF 会引入脸型、躯干、服装和初始姿态差异。
- **待机全局计时，动作局部计时。** 呼吸、摇摆不随点击重启；局部动作结束回 neutral 参数。动作结束时的世界位置应等于同一全局时刻的待机位置，而非强行回到时间零的画面。
- **通道独立。** 例如眼睛与捧花可叠加，同部位可限量排队。若要打断，从当前参数及速度过渡；不要用整张角色画面的交叉淡化掩盖姿态差异。
- **根变换只做一次。** 主窗已有悬浮/缩放时，避免再播放烘焙同类运动的素材造成双重摇摆。热区先逆屏幕与角色根变换，再跟随当前骨骼/物件位置判断。
- **身体不能冒充手部动作。** 抬花由肩肘腕和物件联动，不用拉长腰部实现。原画手臂默认刚性旋转，不补成更粗的皮肤圆柱或扩大肩部补片；单图缺少遮挡内容时，缩小可支持动作，或先补齐并审核原画层，不能假装缺失信息已被恢复。
- **固定肘部弯曲方向。** 不根据移动中的腕部连线每帧重新选择 IK 分支；接近伸直时尤其检查速度和加速度，避免换解跳臂。呼吸作用于躯干，保护手臂与持物的轮廓和粗细。
- **头发增幅先保形。** 若局部位移场已把细发丝挤弯，不直接放大系数；优先把原画发束拆为独立层、固定发根后整体旋转，再按需要增加受约束的弯曲。头发读取全局待机时钟，前景遮挡改变覆盖关系，不挤压发束位移。

## 检查与脚本

```text
python scripts/actor_core.py --self-test
python scripts/audit_actor.py --model MODEL/actor.json --clips MODEL/idle.gif MODEL/blink.gif MODEL/bouquet.gif --require-shared-palette --require-matching-endpoints
```

命令从技能目录运行。第二条仅列出实际产出的预览，不要求每个角色都做眨眼或捧花；`--require-matching-endpoints` 用于承诺共用周期、首尾相同的展示版，任意相位片段不要加此参数。`actor_core.py` 是离线参考逻辑，导入后先 `normalize(model)` 再调用采样，不代表应用已具备点击控制。PNG/预览像素检查需要 Pillow；核心数学与参数检查只用 Python 标准库。审计脚本检查已知资源字段；自定义字段应使用 `{ "path": "相对路径" }`，自定义变形与合成仍需调用方验收。

- [actor-contract.md](references/actor-contract.md)：素材描述、轨道、共享时钟、热区及原生接入。
- [quality.md](references/quality.md)：躯干拉伸、粗细变化、换解、颜色跳变及衔接验收。
- [hair.md](references/hair.md)：头发共享待机、保形摆动、发根接缝、蕾丝误入与增幅验收。
- [eyes.md](references/eyes.md)：可选眼部通道，保留本次已验证的眼睑/眼白修复方法。
